1. The parent of the running binary is the SSH session itself, and that becomes orphaned when the SSH session ends. Orphans are killed by the kernel (lol), so nothing is running when we try to curl. Can be confirmed by re-sshing into the target and confirming the process dies by searching for the same process id with ps (`ssh target 'ps -o pid,ppid,sid,cmd -C main'`). Can be fixed by running the binary as a systemd service.

2. A firewall rule on the target is blocking the port 4444. Can be confirmed by checking the firewall config (`sudo nft list ruleset | grep -A3 4444`). Can be fixed by modifying the firewall config to allow inbound traffic on port 4444.
